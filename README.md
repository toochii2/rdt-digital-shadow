# Explainable digital shadow for lateral-flow RDT manufacturing quality

This is the simulator and evaluation code for the paper:

> Kirabo, S., Alsayegh, A. *Towards Trustworthy Quality Decision Support for Lateral-Flow Rapid Diagnostic Test Manufacturing with an Explainable Digital Shadow.* Submitted to ISDIA-2027 (Springer Lecture Notes in Networks and Systems).

All data are generated by the simulator in this repository. It contains no manufacturer, product, batch, supplier, patient or other confidential data, and the parameter values are illustrative only.

## Contents

| Path | Purpose |
|---|---|
| `code/sim.py` | Semi-synthetic model of test-line dispensing and oven drying, which injects five root causes and nuisance factors (base scenario) |
| `code/sim_nonlinear.py` | Stress scenario adding a humidity-by-drying interaction and a deposition threshold |
| `code/sim_shared.py` | Stress scenario in which the humidity and oven faults share sensor channels |
| `code/sim_nonlinear2.py` | Stress scenario with a humidity-by-line-speed interaction and viscous back-pressure |
| `code/experiments.py` | Detectors (univariate SPC, Hotelling T², logistic regression, XGBoost with and without monotone constraints, and the hybrid), plus the evaluation protocol |
| `code/experiments_r2.py` | Comparators added after review (rule-based control and univariate SPC on the digital shadow), two chance levels, per-fault-type results, lot-clustering null, lot-block thresholds, and stress scenarios |
| `code/analysis_r2.py` | Summary of the round-2 analyses and the confirmatory tests |
| `code/analysis2.py` | Summary tables, Holm-corrected paired tests and the key numbers used in the paper |
| `code/figures_r2.py` | Figures 1 to 4 as published (PNG at 800 dpi, and vector PDF) |
| `results/` | Outputs from the ten evaluation replications (seeds 10 to 19) |
| `figures/` | Figures as published |

## Reproducing the paper

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
./reproduce.sh
```

The code was run with Python 3.13 and the exact package versions pinned in `requirements.txt`. Design iterations used seeds 0 to 9. Every reported result uses the held-out seeds 10 to 19. The round-2 comparators and stress scenarios were added after earlier results on these seeds had been seen, as the paper states.

You can also run each experiment mode on its own from `code/`:

| Command | Paper section |
|---|---|
| `python3 experiments.py main` | §4.1 to §4.3, learned detectors, attribution and ablations |
| `python3 experiments.py containment` | §4.2, containment sensitivity |
| `python3 experiments.py stability` | §4.3, bootstrap stability |
| `python3 experiments.py shared` | §4.3, shared-channel scenario |
| `python3 experiments.py robust` | Sensor dropout, milder faults and extra noise (learned detectors) |
| `python3 experiments.py lowprev` | Low-prevalence stress test |
| `python3 experiments_r2.py main` | Table 2, Fig. 4a, §4.2 to §4.4 (rules, SPC on the DS, chance levels, clustering, lot-block thresholds) |
| `python3 experiments_r2.py lofo` | Fig. 4b, fault types withheld from training |
| `python3 experiments_r2.py stress_mild`, `stress_shared` and `stress_nonlinear2` | §4.4, stress scenarios |
